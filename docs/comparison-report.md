# Novel2Script 对比实验报告

## 实验目的

本报告用于说明 Novel2Script 相比“直接让大模型生成剧本”的差异。重点不比较模型本身强弱，而是比较**生成流程是否可控、输出结构是否可校验、结果是否便于继续编辑和交付**。

## 对比对象

| 方案 | 说明 | 主要限制 |
|------|------|----------|
| Novel2Script | 章节分析、角色提取、场景规划、剧本生成、Schema 校验/修复 | 生成链路较长，AI 模式依赖模型接口 |
| 通用聊天式生成 | 使用一次 Prompt 直接生成剧本正文 | 结构不稳定，难以自动校验和批量处理 |
| 传统手工改编 | 作者或编剧手动整理角色、场景、对白 | 质量可控但耗时高，不适合快速初筛 |

## 测试材料

项目内置样例位于 `examples/`：

- `novel-sample-1.txt`：都市题材，3 章
- `novel-sample-2.txt`：悬疑题材，5 章
- `novel-sample-3.txt`：古装武侠题材，4 章
- `script-output-1.yaml`：Mock 模式标准输出，可通过 Schema 校验

这些样例可以在无 API Key 的 Mock 模式下复现完整流程，也可以在配置模型后切换到 AI 模式评估真实生成质量。

## 对比维度

| 维度 | Novel2Script 观察点 | 直接生成剧本的常见问题 |
|------|---------------------|------------------------|
| 角色一致性 | 角色拥有稳定 ID，如 `CHAR001`，可记录别名和关系 | 角色名称容易混用，后续批量替换困难 |
| 场景结构 | 场景拥有 `id`、地点、时间、出场角色、来源章节和目的 | 场景往往只是自然语言段落，难以检索和排序 |
| 格式校验 | JSON Schema 检查必填字段、类型、枚举和引用关系 | 需要人工判断格式是否完整 |
| 可编辑性 | YAML 可用 Monaco 编辑、复制、下载、版本快照 | 纯文本修改后难以保证引用一致 |
| 交付能力 | 支持 YAML/JSON/Markdown/PDF 导出 | 通常需要二次排版或手工转换 |

## 样例观察

以 `examples/script-output-1.yaml` 为例，Novel2Script 输出包含以下结构：

```yaml
script:
  source:
    chapters:
      - id: C001
        title: 第一章
  characters:
    - id: CHAR001
      name: ...
      first_appearance: C001
  scenes:
    - id: S001
      source_chapters: [C001]
      characters: [CHAR001]
      beats:
        - type: dialogue
          character: CHAR001
          text: ...
```

这类结构带来两个直接收益：

1. **机器可检查**：`script.schema.json` 可以判断字段是否缺失、ID 是否符合规范、场景是否引用了不存在的角色或章节。
2. **人工可继续创作**：编剧可以在 YAML 中定位角色、场景和对白，也可以导出 Markdown/PDF 给非技术成员阅读。

## 工程验证

当前项目使用以下测试保障流程稳定性：

| 测试类型 | 覆盖内容 |
|----------|----------|
| 后端 pytest | 章节解析、生成流程、Schema 校验、项目/版本/导出 API |
| 前端 Vitest | 输入组件、YAML 编辑器、校验面板等核心 UI |
| Playwright E2E | 自动启动前后端，完成识别章节、生成 Mock 剧本、保存项目 |
| Smoke Test | 健康检查、解析、生成、校验、保存、版本和导出主链路 |

## 结论

Novel2Script 的优势不在于“模型一定比通用聊天工具更会写剧本”，而在于它把小说改编拆成了更可控的工程流程：

- 用多阶段生成降低一次性输出漂移；
- 用 Schema 把结果变成可校验的数据结构；
- 用项目和版本管理承接后续修改；
- 用多格式导出支持展示、阅读和程序集成。

因此，本项目更适合用于**剧本初稿生成、网文 IP 初筛、教学/实训演示、结构化创作数据管理**等场景。对于最终成片级对白和细腻戏剧张力，仍需要人工编剧继续润色。

## 可复现实验建议

1. 在 Mock 模式下运行 `scripts/smoke-test.ps1` 或 `bash scripts/smoke-test.sh`，确认完整工程链路。
2. 打开前端工作台，使用 `examples/novel-sample-1.txt` 生成剧本并导出 Markdown/PDF。
3. 将同一小说片段交给通用聊天模型直接生成剧本，对比角色一致性、场景元数据和后续编辑成本。
4. 在 AI 模式下重复测试，记录不同模型的生成时间、校验错误和修复成功情况。
