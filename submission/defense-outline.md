# Novel2Script 答辩提纲

## 1. 开场

Novel2Script 面向小说改编剧本的早期创作环节，目标是让作者快速获得结构化、可编辑、可校验的剧本初稿。

## 2. 痛点分析

- 小说和剧本表达方式不同，改编需要专业经验。
- 长文本改编容易丢失角色、场景和剧情对应关系。
- 纯文本 AI 输出格式不稳定，不方便继续编辑和导出。
- 内容团队需要快速评估多个章节的改编潜力。

## 3. 产品方案

系统从小说文本出发，先识别章节，再生成角色表、场景和剧本 beats，最终输出 YAML。用户可以编辑、校验、保存版本并导出多种格式。

## 4. 技术架构

- React 工作台负责输入、状态展示、YAML 编辑和项目操作。
- FastAPI 提供章节解析、生成、校验、项目和导出接口。
- Prompt 模板、Schema、业务服务分离。
- SQLite 保存本地项目和版本。
- Docker Compose 支持最终部署演示。

## 5. 核心流程

```text
小说输入 -> 章节识别 -> Mock/AI 生成 -> YAML Schema 校验 -> 编辑 -> 保存 -> 版本 -> 导出
```

## 6. Schema 设计亮点

- 顶层 `script` 统一描述标题、类型、来源、角色、场景和改编说明。
- `characters` 统一角色 ID，减少名称不一致。
- `scenes.source_chapters` 保留来源章节追溯。
- `beats.type` 限定动作、对白、旁白、转场和备注。
- 校验不仅检查字段，也检查角色和章节引用合法性。

## 7. AI 生成链路

AI 模式采用五阶段：

1. 章节分析。
2. 角色提取。
3. 场景规划。
4. 剧本 YAML 生成。
5. 校验失败后的自动修复。

默认演示使用 Mock 模式，不依赖真实 API Key。AI 模式需要配置环境变量，并会把小说内容发送给模型供应商。

## 8. 测试与稳定性

- 后端 pytest 覆盖章节解析、边界输入、YAML 校验、Mock 生成和项目导出。
- 前端 smoke test 检查关键状态和入口。
- 端到端 smoke test 覆盖后端健康、解析、生成、校验、保存、版本、导出和前端可访问。
- Docker Compose 和启动脚本降低演示环境不确定性。

## 9. 演示安排

使用 `examples/novel-sample-1.txt`：

1. 识别 3 个章节。
2. Mock 生成 YAML。
3. 展示角色表、场景和 beats。
4. 修改并校验 YAML。
5. 保存项目和版本。
6. 导出 YAML、JSON、Markdown。

## 10. 风险与后续计划

- AI 内容质量需要人工复核。
- SQLite 当前适合本地单机，不适合多人协作。
- 后续可扩展 Word 导出、角色关系图、场景卡片、版本差异和对白润色。
