测试用例覆盖要求

请尽量覆盖 docs/requirements.md 中的 TC001-TC010。

## 必须自动化覆盖

### TC001 标准 3 章节小说

要求：

- 使用 examples/novel-sample-1.txt。
- 后端章节解析返回 3 章以上。
- valid=true。
- mock 生成接口返回 YAML。
- 返回 YAML 通过校验。

### TC002 章节不足

要求：

- 使用 2 章节输入。
- 后端章节解析返回 valid=false。
- message 明确说明章节数量不足。
- 前端生成按钮应在章节 invalid 时禁用。

### TC003 无法识别章节

要求：

- 使用无明显章节标记的纯文本。
- 后端章节解析返回 valid=false。
- message 明确说明无法识别章节格式或章节数量不足。

### TC004 超长章节

要求：

- 构造至少一个超过 10,000 字的章节。
- 后端应返回 warning。
- warning 不阻止 valid 章节生成，除非总输入超限。
- 前端应以警告样式展示 warnings。

### TC005 多种章节格式混合

要求：

- 覆盖“第一章”“Chapter 2”“3.”“卷一 第四章”等格式。
- 后端应识别为多个章节。
- 章节 ID 应从 C001 递增。

### TC007 YAML 校验失败

要求：

- 使用 invalid-script-missing-required.yaml 测试缺少必填字段。
- 使用 invalid-script-bad-reference.yaml 测试角色或章节引用错误。
- 后端返回 valid=false。
- errors 中包含可读错误信息。
- 前端重新校验后不清空用户编辑内容。

### TC008 / TC009 输入边界

要求：

- 测试接近 50,000 字输入。
- 测试超过 50,000 字输入。
- 超限时应拒绝处理，并给出明确错误。
- 超过最大章节数 20 时应拒绝或返回 invalid，并说明原因。

## 可文档化验收

以下项目在未接入真实 AI 前不强制要求真实生成质量自动化通过，但需要通过 fixture 或测试报告说明当前 MVP 如何验证：

- TC006 角色名称一致性
- TC010 复杂人物关系

可以通过 examples/script-output-1.yaml 或新增 YAML fixture 验证：

- 角色 ID 唯一。
- aliases / relationships 字段结构正确。
- scenes[].characters 引用角色表中存在的角色。
- dialogue beat 的 character 引用合法。
