====================
生成模式要求
====================

必须保留两种模式：

## 1. Mock 模式

用途：

- 无 API Key 时演示。
- 自动化测试。
- 前后端联调。

要求：

- 默认仍为 Mock 模式。
- 不调用真实 AI。
- 行为不能被第五阶段破坏。

## 2. AI 模式

用途：

- 调用真实模型生成剧本。

要求：

- 通过环境变量启用，例如：

```env
ENABLE_AI_GENERATION=true
MODEL_PROVIDER=openai
MODEL_NAME=...
MODEL_API_KEY=...
MODEL_BASE_URL=...
MODEL_TEMPERATURE=0.7
MODEL_MAX_TOKENS=4000
MODEL_TIMEOUT=120
AUTO_FIX_ATTEMPTS=3
```

- 允许 OpenAI 兼容 API。
- 不要硬编码某个“最新模型”。
- 模型名称必须来自环境变量。
- 如果 API Key 缺失、依赖缺失、模型调用失败，应返回清晰错误。

====================
分阶段生成流程要求
====================

请完善 AI 模式下的生成流程：

1. 阶段 1：章节分析
   - 输入 title、genre、chapters。
   - 输出结构化 JSON。
   - 应包含章节摘要、主要人物、关键事件、地点、冲突、可转化对白。

2. 阶段 2：角色提取
   - 输入章节分析结果。
   - 输出结构化 JSON。
   - 应生成统一角色表，包含 id、name、role、description、personality、first_appearance、aliases、relationships。

3. 阶段 3：场景规划
   - 输入章节分析和角色表。
   - 输出结构化 JSON。
   - 应生成场景大纲，包含 id、title、source_chapters、location、time、characters、purpose。

4. 阶段 4：剧本 YAML 生成
   - 输入原章节、章节分析、角色表、场景规划。
   - 输出完整 YAML。
   - YAML 必须包含 script 顶层字段。

5. 阶段 5：校验与修复
   - 使用现有 validate_script_yaml 校验。
   - 如果失败，调用 05_yaml_fix.txt 修复。
   - 最多尝试 AUTO_FIX_ATTEMPTS 次。
   - 每次修复后必须重新校验。
   - 如果最终仍失败，应返回最后 YAML 和 validation errors，不应静默伪装成功。

====================
AI 输出解析要求
====================

请增强解析鲁棒性：

1. 支持直接 JSON。
2. 支持 Markdown ```json 代码块。
3. 支持直接 YAML。
4. 支持 Markdown ```yaml 代码块。
5. 支持模型在 YAML 前后添加少量说明时提取 YAML 主体。
6. JSON 解析失败时错误中应包含阶段名和响应片段，但不要输出过长内容。
7. YAML 解析失败时错误中应包含阶段名和可读原因。

注意：

- 阶段 1-3 应尽量要求并解析 JSON。
- 阶段 4-5 应提取并校验 YAML。
- 不要用简单字符串拼接伪造成功结果。

====================
长文本与 token 控制要求
====================

请处理输入较长时的风险。

最低要求：

1. 保留 50,000 字输入上限。
2. 保留 20 章上限。
3. 单章节超过 10,000 字时已有 warning，但 AI 模式下应避免无控制地塞入过长 Prompt。

建议实现：

- 如果章节内容较长，阶段 1 可以按章节逐章分析，再汇总结果。
- 或在 Prompt 中明确只保留每章前后关键片段和章节摘要。
- 如果无法可靠处理，应返回清晰错误或文档化限制。

不要为了长文本处理引入复杂数据库或异步任务系统。
