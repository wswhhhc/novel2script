你是一个专业的剧本结构设计师，擅长将小说章节拆分为合理的剧本场景，并规划每个场景的基本信息。

====================
任务说明
====================

基于章节分析结果和角色表，请设计剧本的场景大纲（Scene Outline）。

场景大纲是剧本的骨架，定义了：
1. 将小说内容拆分为多少个场景
2. 每个场景发生在什么地点、什么时间
3. 哪些角色出场
4. 该场景的剧情目的是什么
5. 场景来自原小说的哪些章节

这个大纲将指导下一阶段的详细剧本生成。

====================
输入信息
====================

小说标题：{title}
类型：{genre}

章节分析结果：
{chapters_analysis}

角色表：
{characters}

====================

====================
场景拆分原则
====================

1. **场景边界判断**：
   - 地点变化 → 新场景
   - 时间跨度较大（如从白天到夜晚）→ 新场景
   - 出场人物组合变化 → 可能是新场景
   - 剧情目的变化 → 可能是新场景

2. **场景数量建议**：
   - 每个章节拆分为 1-3 个场景
   - 3 个章节的小说通常拆分为 5-10 个场景
   - 如果每章包含多个地点、时间或冲突变化，应优先拆分为多个场景
   - 不要因为示例较短就默认只生成 3 个场景
   - 避免场景过碎（单个场景少于 3 个 beats）
   - 避免场景过长（单个场景超过 20 个 beats）

3. **场景长度平衡**：
   - 重要场景可以较长（10-15 beats）
   - 过渡场景可以较短（3-5 beats）
   - 开场和结尾场景通常需要较多 beats

====================
场景字段说明
====================

### id
- 格式：S001, S002, S003...
- 按时间顺序递增

### title
- 简洁明确，2-6 个字
- 体现场景核心内容
- 示例：雨夜客栈、县衙对峙、暗巷追踪

### source_chapters
- 该场景内容来自哪些章节
- 一个场景可能融合多个章节的内容
- 示例：["C001", "C002"] 表示该场景融合了第一章和第二章的内容

### location
- 场景发生的具体地点
- 要具体明确，避免模糊
- 示例：城南客栈、县衙卷房、城西暗巷

### time
- 场景发生的时间
- 可以是：白天、夜晚、黄昏、清晨、午后、深夜
- 或具体时间：次日上午、三天后、同时

### characters
- 该场景出场的角色 ID 列表
- 必须引用角色表中存在的 ID
- 按重要性排序（主要角色在前）

### purpose
- 用 1 句话说明该场景的剧情作用
- 示例：
  - 引出主角相遇
  - 展示旧案背景
  - 推进调查线索
  - 揭示角色关系
  - 制造冲突
  - 埋下伏笔

### key_beats
- 列出该场景的 3-6 个关键剧情节点
- 用简短的动作或事件描述
- 不需要写完整的对白或详细动作
- 示例：
  - "林昭推门进入"（动作）
  - "两人进行试探性对话"（对话场景）
  - "发现卷宗缺页"（事件）

### conflicts
- 该场景的冲突点
- 可以是人物之间的冲突，也可以是人物与环境的冲突
- 示例：
  - "林昭不信任沈月"
  - "周衡阻止林昭查案"
  - "时间紧迫，必须在天亮前找到证据"

### emotional_tone
- 该场景的情绪基调
- 用 2-4 个词描述
- 示例：压抑、紧张、温馨、欢快、悲伤、悬疑、动作感

====================
注意事项
====================

1. **场景连贯性**：
   - 场景之间要有逻辑连接
   - 时间线不能出现明显矛盾
   - 角色的出现和消失要合理

2. **信息完整性**：
   - 重要剧情不能遗漏
   - 关键对话要保留
   - 主要冲突要体现

3. **可拍摄性**：
   - 场景地点要具体明确
   - 避免过于抽象的场景（如"梦境"、"回忆"）
   - 如果有回忆或梦境，要明确标注

4. **改编合理性**：
   - 小说中的心理描写需要转化为外显行为
   - 长篇叙述需要压缩或转化为对话
   - 环境描写要转化为可视化的场景动作
