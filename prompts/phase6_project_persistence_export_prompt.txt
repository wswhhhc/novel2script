你是一个资深全栈工程师，擅长产品化 MVP、数据建模、导出系统和前后端集成。请基于当前已经完成的 Novel2Script 项目，完成第六阶段任务：项目持久化与多格式导出。

====================
重要说明
====================

【阶段定位】第六阶段是 MVP 的增强扩展，不在原需求文档的 MVP 核心范围内。

原需求文档（docs/requirements.md）明确指出以下功能”暂不实现”：
- 用户登录和权限管理
- 多人协作编辑
- 在线版本管理

但基于以下原因，建议实现轻量级项目持久化功能：

1. **用户体验**：无保存功能的工具实用性严重不足，用户无法保留工作成果
2. **产品完整度**：项目保存是创作工具的基础能力
3. **技术可行性**：SQLite 本地存储，无需登录、云同步等复杂基础设施
4. **范围可控**：仅实现本地持久化，不涉及多人协作和云服务

【实施建议】
- 如果项目时间紧张或需要严格遵守原 MVP 定义，可以跳过本阶段
- 如果决定实施本阶段，请先更新 docs/requirements.md，将”项目本地保存和导出”从”暂不实现”移至”MVP 扩展功能”
- 可以选择实施完整版或简化版（见下文”实施方案选项”）

====================
任务背景
====================

项目名称：Novel2Script：AI 小说转剧本创作助手

项目目标：
开发一款 AI 辅助剧本创作工具，支持用户输入 3 个章节以上的小说文本，自动生成符合 YAML Schema 的结构化剧本初稿，并允许用户继续编辑、校验、保存和导出。

当前已经完成：

- 第一阶段：需求、Schema、Prompt 模板和标准 YAML 示例
- 第二阶段：FastAPI 后端核心接口
- 第三阶段：React 前端工作台
- 第四阶段：测试优化、示例数据和验收文档
- 第五阶段：真实 AI 生成链路接入与稳定化

第六阶段目标是让工具从”一次性生成器”升级为”可保存、可回看、可导出”的轻量创作工作台。

数据模型要求
====================

请根据选择的方案设计数据模型。

## 方案 A：简化版数据模型

### Project 表

表示一个小说转剧本项目。

建议字段：

- id: string 或 int (主键)
- title: string (必填)
- genre: string (必填)
- source_content: text (必填，原始小说文本)
- chapter_count: int
- chapters_json: text (JSON 字符串，存储章节列表)
- current_yaml: text (当前 YAML 剧本)
- validation_json: text (JSON 字符串，存储校验结果)
- generation_mode: string (mock / ai)
- created_at: datetime
- updated_at: datetime

要求：
- 每次保存项目时更新 current_yaml 和 updated_at
- 不保留历史版本，只保留最新状态
- 删除项目即删除该记录

## 方案 B：完整版数据模型

### Project 表

表示一个小说转剧本项目。

建议字段：

- id: string 或 int (主键)
- title: string (必填)
- genre: string (必填)
- source_content: text (必填，原始小说文本)
- chapter_count: int
- chapters_json: text (JSON 字符串，存储章节列表)
- current_yaml: text (当前 YAML 剧本)
- validation_json: text (JSON 字符串，存储校验结果)
- generation_mode: string (mock / ai)
- created_at: datetime
- updated_at: datetime

### ScriptVersion 表

表示某个项目的一次 YAML 版本快照。

建议字段：

- id: string 或 int (主键)
- project_id: 外键 → Project.id
- version_name: string (必填，如 "初稿 v1")
- yaml: text (必填，版本快照的 YAML 内容)
- validation_json: text (JSON 字符串，存储该版本的校验结果)
- note: text (可选，版本说明)
- created_at: datetime

关系：
- 一个 Project 可以有多个 ScriptVersion
- 删除 Project 时级联删除其所有 ScriptVersion

要求：
- 保存项目时更新 Project.current_yaml
- 用户手动保存版本时创建新的 ScriptVersion 记录
- 恢复版本时将 ScriptVersion.yaml 复制到 Project.current_yaml

后端接口要求

请根据选择的方案实现相应接口。

## 方案 A：简化版接口（5 个项目管理接口 + 3 个导出接口）

### 项目管理接口

#### 1. 创建项目

POST /api/projects

请求：

```json
{
  "title": "长夜初逢",
  "genre": "悬疑",
  "source_content": "小说全文",
  "chapters": [],
  "yaml": "script:\n  title: ...",
  "validation": {
    "valid": true,
    "errors": []
  },
  "generation_mode": "mock"
}
```

响应：

```json
{
  "id": 1,
  "title": "长夜初逢",
  "genre": "悬疑",
  "chapter_count": 3,
  "generation_mode": "mock",
  "created_at": "2026-06-05T10:00:00Z",
  "updated_at": "2026-06-05T10:00:00Z"
}
```

#### 2. 项目列表

GET /api/projects

响应：

```json
[
  {
    "id": 1,
    "title": "长夜初逢",
    "genre": "悬疑",
    "chapter_count": 3,
    "generation_mode": "mock",
    "created_at": "2026-06-05T10:00:00Z",
    "updated_at": "2026-06-05T10:00:00Z"
  }
]
```

#### 3. 项目详情

GET /api/projects/{project_id}

响应应包含：
- 项目基础信息
- source_content
- chapters
- current_yaml
- validation

#### 4. 更新项目

PUT /api/projects/{project_id}

请求：

```json
{
  "title": "长夜初逢（修改版）",
  "genre": "悬疑",
  "yaml": "script:\n  title: ...",
  "validation": {
    "valid": true,
    "errors": []
  }
}
```

用途：
- 更新 title / genre
- 更新 current_yaml
- 更新 validation
- 可选更新 source_content 和 chapters

#### 5. 删除项目

DELETE /api/projects/{project_id}

响应：

```json
{
  "message": "项目已删除",
  "id": 1
}
```

### 导出接口

#### 6. 导出 YAML

GET /api/projects/{project_id}/export/yaml

返回：
- Content-Type: application/x-yaml 或 text/yaml
- Content-Disposition: attachment; filename="{title}_script.yaml"
- 内容为 current_yaml

#### 7. 导出 JSON

GET /api/projects/{project_id}/export/json

要求：
- 将 YAML 解析为 JSON
- 返回 Content-Type: application/json
- Content-Disposition: attachment; filename="{title}_script.json"
- 如果 YAML 当前不合法，应返回 400 错误和明确提示

#### 8. 导出 Markdown

GET /api/projects/{project_id}/export/markdown

要求：
- 将 YAML 剧本转换为可读 Markdown
- Content-Type: text/markdown
- Content-Disposition: attachment; filename="{title}_script.md"
- 至少包含：标题、类型、来源章节、角色表、场景列表、改编说明
